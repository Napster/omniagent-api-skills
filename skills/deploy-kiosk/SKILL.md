# deploy-kiosk

Kiosk puts your Omniagent on a **Napster Station** — dedicated hardware for in-person, walk-up conversations (lobbies, retail floors, showrooms, events). Unlike the other channels, the kiosk runs on **Napster hardware, not a client you build and host**.

A Station has two screens: a small one showing the agent's avatar, and a large **experience** screen — a custom, branded app the agent presents and *drives* as it talks (products, wayfinding, promotions, an exhibit guide). A visitor talks to the agent; the agent surfaces the right content on the big screen as the conversation unfolds.

<Callout type="warn">
**Kiosk is gated.** It needs a physical Napster Station, and the experience app is built and wired up together with the Napster team. See [napster.com/station](https://napster.com/station) and [contact Napster](https://help.napster.com) to get set up. You can configure the channel via the API (below), but pairing the Station and deploying the experience happens with Napster.
</Callout>

## Prerequisites

- An **agent ID** (`agent_…`). If you don't have one, route to [[create-agent]]. A clear persona and a set `language` help for spoken, walk-up use.
- A **Napster Station** (arranged with Napster — see above).
- An **experience** — the app that runs on the big screen. It's a separate application **you build and host**; it isn't generated by Napster. Because it's bespoke to the Station, building and wiring it is done with the Napster team.

## Configure the kiosk channel

`PUT` the `kiosk` channel config on the agent. Name the experience with `theme`, point at it with `url`, and use `initialSpeech` to tell the agent how to open with each visitor.

```bash
curl -X PUT https://companion-api.napster.com/public/agents/agent_abc123/channels/kiosk \
  -H "X-Api-Key: $NAPSTER_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "theme": "Lobby Concierge",
    "url": "https://experiences.example.com/lobby-concierge",
    "initialSpeech": "Greet the visitor warmly, say you can help them find their way around, and ask what they are looking for."
  }'
```

```python
import os, requests
requests.put(
    "https://companion-api.napster.com/public/agents/agent_abc123/channels/kiosk",
    headers={"X-Api-Key": os.environ["NAPSTER_API_KEY"]},
    json={
        "theme": "Lobby Concierge",
        "url": "https://experiences.example.com/lobby-concierge",
        "initialSpeech": "Greet the visitor and ask what they are looking for.",
    },
)
```

### Fields

| Field | Description |
|---|---|
| `theme` | The name of the experience that runs on the Station's main screen. |
| `url` | The hosted URL of that experience. |
| `initialSpeech` | How the agent opens with each visitor (an instruction, not a verbatim line). |
| `functions` | Use different tools on the kiosk than on other channels. |
| `faqCollections` | Use different FAQs on the kiosk. |
| `knowledgeBaseId` | Use a different knowledge base on the kiosk. |
| `providerSettings` | Override temperature, turn detection, and noise reduction for the room. |
| `useWebSearch` | Enable or disable web search on the kiosk. |
| `idleTimeoutSeconds` | How long to wait before ending an inactive conversation and resetting for the next visitor — core to walk-up use. |

Omit the overrides to inherit the agent's defaults. Like the phone channel — and unlike WebRTC/WebSocket — the kiosk config is **persistent**: set it once and it stays until you change or remove it.

## Managing the channel

```bash
# Get current kiosk config
curl https://companion-api.napster.com/public/agents/agent_abc123/channels/kiosk \
  -H "X-Api-Key: $NAPSTER_API_KEY"

# Remove the kiosk channel config
curl -X DELETE https://companion-api.napster.com/public/agents/agent_abc123/channels/kiosk \
  -H "X-Api-Key: $NAPSTER_API_KEY"
```

## Verify

You can't drive the physical Station yourself — hand the in-person check to the developer/Napster. What you *can* confirm: the `PUT` returns the config with your `theme`/`url`, and once the Station is live, kiosk conversations show up in [[monitor-sessions]] with `sessionType: "kiosk"`.

## Common errors

| Symptom | Likely cause | Fix |
|---|---|---|
| Experience screen blank | `url` not publicly reachable, or experience not deployed to the Station | Host the experience on public HTTPS; deploy it with the Napster team |
| Nothing happens on the Station | Station not paired to this agent | Pairing is done with Napster — confirm the Station is bound to the right agent |
| Agent behaves like other channels | No kiosk overrides set | Add `functions`/`faqCollections`/`knowledgeBaseId`/`providerSettings` to tailor the kiosk |
